# GE4G Basement architecture

Stable Rust, edition 2024. Seven populated workspace packages implement the current boundaries; no ECS framework or complete external game engine is imported.

| Package | Responsibility | Engine dependencies |
| --- | --- | --- |
| `ge4g-core` | Versioned types, integer math, input, typed state, snapshots, events | None |
| `ge4g-project` | TOML/JSON5 parsing, validation, PNG texture decoding, atomic file output | Core |
| `ge4g-runtime` | Authoritative world, fixed-step systems, scenes, saves, assertions and hashes | Core, project |
| `ge4g-render2d` | CPU frame construction and PNG output | Core, project |
| `ge4g-platform` | Optional minifb window, keyboard input and wall-clock scheduling | Core, project, runtime, render2d |
| `ge4g-client` | Version 1 C/JSON ABI, owned sessions and copied CPU frames for Flutter | Core, project, runtime, render2d |
| `ge4g-cli` | Commands, JSON presentation, project replay test orchestration | All above |

## Simulation and coordinates

`World::step(Input)` advances exactly one simulation tick at 60 Hz. It never reads the clock, window, filesystem or network. Input opposing directions cancel. Movement is per-axis; diagonal motion has full speed on both axes. There is no random gameplay and therefore no seed flag.

Authored coordinates are integer pixels. Authoritative positions are signed `i64` units at 60 subpixels per pixel. At 60 Hz, speed in pixels/second equals the integer displacement per axis per tick. Snapshots expose `subpixels_per_pixel` and `tick_hz`; no floating-point gameplay calculation is required.

Walls use swept AABB clamping, resolving X then Y. Axis motion paths also detect crossed door triggers, preventing fast motion from skipping them. Strict overlap excludes merely touching edges. Player and transition-spawn penetration is rejected before runtime.

Replay input index 0 advances the world from tick 0 to tick 1. Input spans are `[start,end)`. Events generated by that step are stamped tick 1. Explicit headless execution provides pause/step behavior by making no call or calling `step` once; `run --headless --ticks N` is the CLI path.

## World and behavior order

Entities are stored in a `BTreeMap` by stable scene-local identifier. Entity identity is `(scene,id)`; the demo uses `player` in both scenes. Each tick performs movement and blocking collision, edge-triggered interaction, then trigger processing. X/Y resolution, eligible interaction targets and competing door triggers have deterministic ordering. One interaction and at most one scene transition occur per tick.

NPC proximity expands the NPC's AABB by its authored range. A rising `interact` input emits dialogue, writes typed state and emits an audio cue event. Holding the key does not repeat dialogue. Declarative behaviors have no arbitrary script, filesystem, process or network execution surface.

Entering a scene loads fresh entities, selects an explicit named spawn for transitions, clears contact bookkeeping and applies `on_enter` state writes in sorted key order. Input remains held across transitions, preserving interaction edge semantics. Persistent state is owned by the world, not the scene.

## Rendering and adapters

`Snapshot -> sorted render list -> CPU RGBA Frame -> PNG or window` is the only render path. Draw order is `(layer,id)`. Camera translation is integer pixels; subpixel positions round down, including negatives. PNG textures use deterministic nearest-neighbor scaling and integer straight-alpha blending. Debug outlines are applied after sprites. There is no text/font dependency in captures.

The minifb window presents these CPU pixels. Its clock schedules fixed steps and clamps a delayed display update to 250 ms of catch-up. Keyboard state is normalized to the same `Input` consumed by replays. P pauses, N performs one step while paused. No simulation logic lives in this adapter. The `window` feature can be omitted entirely.

`sound` produces observable cue events; `music` owns serializable logical loop state. Flutter audio adapters and the Rust window audio backend play declared files. Headless records the same events independently of audio devices. Playback completion never controls gameplay.

## Observation and persistence

All public formats start at schema version 1. The runtime retains the latest 4,096 events and reports the exact number dropped. Trace export can select event kinds and preserves order. A project test rejects overflow so its complete final gameplay event comparison is meaningful.

Snapshots contain the scene, tick, camera, entities/components, state and event history. They are inspectable artifacts, not whole-world save formats. The canonical deterministic hash is SHA256 of serialized snapshot JSON. Paths in `save_written` affect this hash, so gameplay repeatability is compared before save side effects.

Schema1 legacy saves contain project identity and typed persistent keys. Schema2 saves additionally preserve the whole world, scene, RNG, event/battle controller, persistent view and combatants. Content revision, actor state and candidate collision are validated before committing. Resume does not replay rewards, damage, PP or event advancement. `ResumeError::ContentRevisionMismatch` crosses ABI1 as `error_code:save_content_revision_mismatch`; corrupt/invalid saves remain distinct errors.

Artifact writes use a unique temporary file in the destination directory, flush and sync, then atomic replacement. On Unix the parent directory is also synced. Output directories must already exist. PNGs, saves, traces and snapshots share this path.

## Diagnostics and limits

Errors include operation and source file/entity/tick when relevant. Unknown fields and schema versions are rejected. Project-local asset/replay/scene references cannot leave the project root, including through symlinks. External replay/save/output paths supplied on the CLI are explicit user selections.

File text is limited to 16 MiB, frame and texture dimensions to 2048, scenes to 128, entities per scene to 4096, authored coordinates to ±1,000,000 pixels, player speed to 60,000 pixels/second, and runtime/replay duration to 1,000,000 ticks. Generated schemas cover structure; `validate` enforces these semantic limits and references.

## Flutter runtime adapter

`client/` owns native-platform presentation, import/library storage, keyboard/touch routing, fixed 60 Hz scheduling and live JSON control editing. `ge4g_native` builds the Rust ABI as a bundled code asset. `World::step_actions` wraps the unchanged deterministic step and adds sorted named action edge events. `release_inputs` releases held actions/interact without a simulation tick. The ABI holds at most eight opaque sessions and copies frame bytes into caller-owned buffers; C strings have an explicit free function. Each ABI response identifies version 1. Mobile never spawns the CLI and imported data never supplies executable code.

Game packages, layout profiles, per-game bindings and saves are separate durable surfaces; see [CLIENT](CLIENT.md). Desktop distributions set embedded mode alongside their executable, include the full Flutter bundle and open their game directly.

## Library activation and cutscene labels

GameLibrary validates staged packages, serializes index mutations and preserves stable
game_id/order. Player closes native sessions, settles frame/audio work and leases
immutable content until release. Update activation backs up saves/settings and rolls
back on open failure. Typed incompatible saves are archived and opened fresh; only
confirmed successful activation retires inactive content. Library manager is separate
from embedded game presentation. Speakers resolve in Rust; Flutter renders optional
headers and never owns simulation or save-compatibility decisions.
